# Безопасность XAVAMOS Digital Urpaq

Результаты аудита текущей архитектуры и перечень мер. Это учебный прототип: локальная работа ≠ готовность к публичной эксплуатации — см. «Остаточные риски».

## Аутентификация и сессии

- Пароли хранятся как **Argon2id** (`argon2-cffi`), проверка выполняется даже для несуществующего пользователя (защита от перебора по времени ответа).
- **JWT (HS256)** с `exp`, `jti`, `iat`; срок — `ACCESS_TOKEN_MINUTES` (480). Logout заносит `jti` в `revoked_tokens`; просроченные записи удаляются.
- Роль **не берётся из токена**: на каждый запрос пользователь перечитывается из БД (`deps._user_from_token`), заблокированный пользователь теряет доступ немедленно.
- Токен хранится в `localStorage` (bearer). Это означает, что XSS-уязвимость даёт доступ к токену. Снижение риска: React экранирует вывод, `dangerouslySetInnerHTML` не используется, зависимости минимальны, security-заголовки включены. Переход на HttpOnly-cookie + CSRF-токен возможен, но не внедрён, чтобы не менять архитектуру вслепую.
- Лимит попыток входа: `LOGIN_RATE_LIMIT_PER_MINUTE` на IP (sliding window, в памяти процесса; за прокси включите `TRUST_PROXY_HEADERS`). Для нескольких воркеров добавьте лимит на reverse proxy.

## Авторизация

- RBAC на сервере: `observer` (чтение), `operator` (+ обработка предупреждений, управление симулятором, ingest), `admin` (+ станции, пользователи, настройки, аудит).
- Все проверки — зависимости FastAPI (`require_operator`, `require_admin`); скрытие элементов в UI — только удобство.
- Защита от self-lockout и удаления последнего администратора.
- Публичный фид событий `/api/events/recent` отдаёт только события `alert/simulator/station`; `auth.*`, `user.*`, `settings.*` доступны лишь администратору через `/api/audit-log`.
- Telemetry ingest: `X-Ingest-Key` (симулятор/устройства) или токен оператора/администратора.

## Валидация входных данных

- Pydantic v2 для всех тел запросов: диапазоны координат, порогов, интервалов, параметров телеметрии (`PARAMETER_RANGES`), запрет NaN/Infinity, обязательный часовой пояс в `measured_at`, ограничение «не из будущего/не старше 30 дней», максимум 20 показаний в сообщении и 50 сообщений в batch.
- Ограничения запросов: `page_size ≤ 200`, диапазон истории ≤ 30 дней, ≤ 5000 точек (автоматическое бакетирование), лимит тела `MAX_REQUEST_BYTES`, тайм-аут 60 с.
- SQL — только через SQLAlchemy ORM/параметризованные выражения; `ilike` с пользовательским вводом экранируется драйвером.
- Единый формат ошибок без stack trace; внутренние исключения логируются на сервере, клиент получает `internal_error`.

## Секреты и конфигурация

- Секреты только в переменных окружения / `.env` (в `.gitignore`); `.env.example` без реальных значений.
- В `APP_ENV=production` приложение **не стартует** с dev-секретами, короткими ключами, localhost в CORS или относительным SQLite-путём (`Settings.production_problems`).
- Swagger/ReDoc в production выключены по умолчанию (`ENABLE_DOCS`).
- Логи и аудит: ключи `password/token/secret/api_key` вырезаются (`audit_service._scrub`); access-log не содержит тел запросов и заголовков авторизации.
- В клиентский bundle попадают только переменные с префиксом `VITE_` (`VITE_API_BASE`, `VITE_APP_VERSION`, `VITE_SHOW_DEMO_ACCOUNTS`) — секретов нет.
- Демо-аккаунты (`admin/operator/observer`) создаются только при `SEED_ON_STARTUP=true` / `python -m app.seed`; в production используйте `scripts/create_admin.py`.

## Транспорт и заголовки

- CORS allowlist (`CORS_ORIGINS`), методы и заголовки ограничены.
- Security-заголовки: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, `Cache-Control: no-store` для `/api/*`.
- TLS терминируется на reverse proxy (см. DEPLOYMENT.md); HSTS/CSP задаются там же.

## Симулятор и фоновые процессы

- Один цикл на процесс (lock + задача), состояние в БД; внешний runner отказывается работать, если жив встроенный драйвер (`simulator_conflict`).
- Управление симулятором — только `operator`/`admin`; статус публичный, но без секретов.
- Идемпотентность по `event_id` исключает дубли при повторной отправке.

## Остаточные риски (не закрыты в прототипе)

| Риск | Статус | Рекомендация |
|---|---|---|
| Bearer-токен в localStorage | принят | HttpOnly cookie + CSRF при переходе в эксплуатацию |
| Лимит входа только в памяти одного процесса | принят | лимит на nginx/Cloudflare для multi-worker |
| Нет 2FA, нет политики сложности паролей кроме длины ≥ 8 (≥ 12 для create_admin) | открыт | добавить при реальном использовании |
| Нет аудита чтения данных | принят | при необходимости логировать на прокси |
| Эвристика риска не валидирована | по дизайну | не использовать для реального оповещения |
