# Алгоритм оценки риска подтопления

> Демонстрационная эвристическая оценка, не валидированный прогноз. Не предназначена для реального экстренного реагирования. Индекс не является вероятностью наводнения.

Реализация: `backend/app/services/risk_engine.py` (версия `1.2.0`, чистый модуль без зависимостей от БД и FastAPI, покрыт unit-тестами `backend/tests/test_risk_engine.py`).

## Входные данные

| Параметр | Единица | Роль |
|---|---|---|
| `water_level_cm` | cm | обязателен; без него — `insufficient_data` |
| `water_level_rate_cm_h` | cm/h | если отсутствует или устарел — вычисляется МНК-наклон по серии уровней |
| `rainfall_mm_h` | mm/h | опционален |
| `soil_moisture_pct` | % | опционален, учитывается только если свежее `soil_stale_after_seconds` (3600 с) |
| серия `water_level_cm` | — | последние `trend_window_points` (8) точек для тренда |

Пороги станции (`station.configuration.thresholds`):

| Ключ | По умолчанию |
|---|---|
| `baseline_level_cm` | 120 |
| `warning_level_cm` | 220 |
| `critical_level_cm` | 300 |
| `critical_rise_rate_cm_h` | 30 |
| `critical_rainfall_mm_h` | 15 |
| `soil_dry_pct` / `soil_saturated_pct` | 20 / 85 |

Системные настройки (`PATCH /api/admin/settings`): веса, пороги категорий, `stale_after_seconds` (900), `soil_stale_after_seconds`, `trend_window_points`, `trend_min_points`, `forecast_horizons_hours`.

## Проверка свежести

1. Нет измерения уровня воды → `risk_level = insufficient_data`, `score = null`.
2. Возраст последнего измерения уровня > `stale_after_seconds` → `risk_level = stale`, `score = null`, в объяснении указывается, сколько минут назад были данные. Предупреждения при этом **не создаются**.

## Компоненты (каждый ограничен диапазоном [0, 1])

```
clamp01(x) = max(0, min(1, x));  safe_ratio(a, b) = clamp01(a / b), 0 если b ≤ 0 или a/b не конечно

normalized_level           = safe_ratio(level − baseline, critical − baseline)
normalized_rise_rate       = safe_ratio(rate, critical_rise_rate)           при rate > 0, иначе 0
normalized_rainfall        = safe_ratio(rain, critical_rainfall)
normalized_soil_saturation = safe_ratio(soil − soil_dry, soil_saturated − soil_dry)
trend_component            = consistency · (1.25 если ускорение)  при направлении "rising"
                           = 0.35 · consistency                   при "stable" с наклоном > 0 и consistency > 0.75
                           = 0                                    иначе
```

Тренд: по последним N точкам считается МНК-наклон `slope_cm_h`, `consistency` — доля положительных приращений, `accelerating` — наклон второй половины окна больше первой на 15 %. Направление: `rising` при slope > 0.5 cm/h, `falling` при slope < −0.5, иначе `stable`. Если точек меньше `trend_min_points` (3) или временной интервал окна < 5 с, тренд недоступен.

## Агрегация

```
score = 100 · Σ_{i ∈ available} (w_i · c_i) / Σ_{i ∈ available} w_i
```

Недоступный компонент (нет свежих данных) исключается и из числителя, и из знаменателя — деления на ноль нет (при Σw = 0 score = 0). Веса по умолчанию: level 0.35, rise_rate 0.25, rainfall 0.20, soil 0.10, trend 0.10.

Категория: `high` если score ≥ 65, `medium` если ≥ 35, иначе `low` (пороги настраиваемы, требуется `0 < medium < high ≤ 100`).

## Объяснение

Для каждой оценки сохраняются `score`, `risk_level`, `assessed_at`, `algorithm_version`, `contributing_factors` (значение, нормировка, вес, вклад в баллах, примечание) и человекочитаемое объяснение на русском и казахском. В текст попадают только факторы, реально участвовавшие в расчёте и давшие заметный вклад (до трёх самых значимых), плюс состояние тренда. Близость к критическому порогу и его превышение указываются явно.

Пример: «Риск высокий (индекс 78/100) из-за близости уровня воды (247 cm) к критическому порогу 280 cm; быстрого роста уровня воды (+42.0 cm/h); интенсивных осадков (23.4 mm/h). Последние измерения показывают продолжающийся подъём.»

## Трендовая оценка на 1–3 часа

`projected = level + slope · h`, где `slope` — скорость подъёма, сообщённая станцией (если свежая), иначе МНК-наклон серии. Полоса неопределённости: `± (2·σ_остатков + 0.35·|slope·h| + 2 cm)`. Это **линейная экстраполяция**, не ML-прогноз; допущение — сохранение текущей скорости изменения. Горизонты задаются `forecast_horizons_hours` (по умолчанию 1 и 3 ч).

## Примеры расчёта (пороги по умолчанию)

### 1. Стабильное состояние
уровень 125, скорость +0.2, осадки 0.4, почва 30 %, серия 124…125 (stable).

| Компонент | c | w | w·c |
|---|---|---|---|
| level | (125−120)/180 = 0.028 | 0.35 | 0.010 |
| rise_rate | 0.2/30 = 0.007 | 0.25 | 0.002 |
| rainfall | 0.4/15 = 0.027 | 0.20 | 0.005 |
| soil | (30−20)/65 = 0.154 | 0.10 | 0.015 |
| trend | 0 | 0.10 | 0 |

score = 100 · 0.032 / 1.0 ≈ **3 → low**.

### 2. Быстрое наводнение
уровень 290, скорость +45, осадки 22, почва 90 %, серия устойчиво растёт (consistency 1.0).

| Компонент | c | w | w·c |
|---|---|---|---|
| level | 170/180 = 0.944 | 0.35 | 0.331 |
| rise_rate | 45/30 → 1.0 | 0.25 | 0.250 |
| rainfall | 22/15 → 1.0 | 0.20 | 0.200 |
| soil | 70/65 → 1.0 | 0.10 | 0.100 |
| trend | 1.0 | 0.10 | 0.100 |

score = **98 → high**; объяснение упоминает близость к критическому порогу 300 cm, рост +45 cm/h и осадки 22 mm/h.

### 3. Только уровень воды (остальные датчики недоступны)
уровень 300, нет других параметров → доступен только `level` с c = 1.0, Σw = 0.35 → score = 100 · 0.35 / 0.35 = **100 → high**, `data_quality.components_used = ["level"]`, `missing_parameters` перечислены.

### 4. Устаревшие данные
последний уровень 290 измерен 33 минуты назад при `stale_after_seconds = 900` → `risk_level = stale`, `score = null`, предупреждение не создаётся.

## Автоматические предупреждения (`alert_service.evaluate_alerts`)

| Ситуация | Действие |
|---|---|
| Категория `high` | нужно предупреждение `high` |
| Переход `low/none/stale/insufficient → medium` (если `alert_on_medium`) | нужно предупреждение `medium` |
| `high → medium` | ничего (деэскалация оставляется оператору) |
| Есть активное (`new`/`acknowledged`) предупреждение по станции и требуемая серьёзность **выше** | **эскалация**: обновляются severity, заголовок, описание, факторы, `escalation_count += 1`, история эскалаций в `trigger_factors.escalations`, запись аудита `alert.escalated` |
| Есть активное предупреждение той же или большей серьёзности | **дедупликация**: ничего не создаётся |
| Последнее закрытое предупреждение той же или большей серьёзности закрыто менее `suppression_minutes` (10) назад | **подавление**: ничего не создаётся (более высокая серьёзность подавление обходит) |

Оператор: `acknowledge` (идемпотентно; на закрытое → 409), `resolve` с причиной (идемпотентно, повторный вызов не меняет первую причину). Все действия фиксируются в `audit_log` с пользователем и временем.

## Ограничения

- Коэффициенты подобраны для наглядной демонстрации, не калиброваны на реальных гидрологических данных.
- Тренд считается по реальным временным меткам; при ускорении симулятора ×N наклон тренда в N раз круче сообщённой скорости.
- Не учитываются морфология русла, снегозапас, прогноз погоды, работа гидроузлов.
